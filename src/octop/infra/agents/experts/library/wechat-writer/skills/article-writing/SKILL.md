# 公众号正文写作

> `scripts/content_check.py` 相对于本技能目录。

## 1. 开头（前 3 句决定读者是否留下）

任选一种，3 句内进入主题：
- **场景代入**："每周五下午，你是不是也在对着空白文档发呆？"
- **结论前置**："上个月我把写周报交给了 AI，每周省下 2 小时。"
- **反常识**："写得越详细的周报，越没人看。"
- **数据冲击**（必须有可靠来源）："某调查显示，〔数据〕……"
- **故事切入**：一个具体的人、一个具体的时刻、一个冲突。

禁止："随着社会的发展……""在当今这个时代……"这类空泛开头。

## 2. 结构模板

| 类型 | 结构 |
|------|------|
| 干货/教程 | 痛点 → 方法总览 → 步骤 1/2/3（每步：做什么 + 为什么 + 示例）→ 常见错误 → 总结清单 |
| 观点 | 现象 → 核心观点 → 论据 1/2/3（数据、案例、类比）→ 反方观点回应 → 结论和行动建议 |
| 故事 | 背景 → 冲突 → 转折 → 结果 → 启发（不说教，点到为止） |
| 案例拆解 | 案例概述 → 关键数据 → 拆解 3 个关键动作 → 可借鉴之处 → 局限 |
| 政策解读 | 一句话说清政策 → 和谁有关 → 变化点（新旧对比）→ 怎么办（办理流程、时间节点）→ 原文链接 |
| 产品/活动推广 | 用户痛点 → 解决方案 → 使用场景/案例 → 信任背书（真实）→ 行动指引（价格、时间、方式） |

## 3. 正文写法

- 小标题：提炼观点，而不是概括话题（"先把素材收集起来"优于"素材收集"）。
- 每个观点配一个例子、数据或场景，不连续说理超过 3 段。
- 金句：每篇 1–3 句，短、对仗或有反差，放在小节结尾；用 `>` 引用块突出。
- 结尾：总结 + 互动问题或行动指引（"你平时怎么写周报？欢迎在评论区聊聊"），不写"喜欢就点赞转发"之类诱导语。
- 篇幅：干货 2000–3000 字；观点 1500–2500 字；资讯 800–1200 字。

## 4. 改稿清单

收到用户的稿子时按顺序检查并给出修改意见和修改稿：
1. 标题与正文是否一致；开头 3 句是否抓人；
2. 结构是否清晰（看小标题能否读懂全文）；
3. 段落是否过长、有无重复和空话；
4. 事实、数据、引用是否有来源；
5. 错别字、标点、"的地得"；
6. 合规风险（运行下面的脚本）。

## 5. 合规自查

```bash
python scripts/content_check.py outputs/wechat/<标题>.md
```

检查广告法极限用语（最佳、第一、顶级、国家级……）、医疗健康功效、金融收益承诺、诱导分享关注、夸大表达。退出码 3 表示有命中：逐条判断语境，确属风险的改写（"最受欢迎"→"很多用户选择"），并在交付时告诉用户改了哪些。脚本只是关键词提示，不能替代法务审核。
