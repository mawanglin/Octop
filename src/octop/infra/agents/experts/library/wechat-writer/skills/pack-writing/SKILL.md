# 按线索包写稿

> `scripts/` 路径相对于本技能目录。

这个技能让你和团队里的采集员、核验员、发布专员接上手：采集员给你“线索包”，你写出“初稿”，核验员逐条对，发布专员只发通过核验的稿子。**平时一个人写稿、用户没有给线索包时，不需要这个技能。**

## 1. 接收

- 文章包在工作区里就直接读；主持人把文字贴在消息里，就先存成文件：
  `python scripts/article_pack.py new outputs/pack/<话题>.md --topic "…"`，再 `put 选题单 / 线索包`（`--file -` 读标准输入）。
- 先读“选题单”（读者、平台、篇幅、风格、禁区），再读线索包每条来源的**状态、可信度和摘录**。
- 线索包缺口太大、关键事实没有可用来源时，不要硬写：告诉主持人需要采集员补充什么。

## 2. 写作规则（核验员会逐条查）

1. **每个带事实的句子，句末标来源**：`… [S1]`，多个来源 `[S1,S2]`。数字、日期、人名、引语、结论都算事实。
2. **只用“可用”来源**；“不可用”的来源一律不引用。
3. **“存疑”或 C 级来源**只能写成限定语气：“有网友反映…”“据称…”“个别说法…”，并且不作为核心结论。
4. **引语逐字**：要引用原话，用引号框起来，内容和摘录一字不差；不确定就改写，不要凭印象“差不多”。
5. **改写要换说法和结构**，不要把摘录改几个字就当自己的话；逐字相同的连续片段只留在引号里。
6. **推算的内容标 `[推算]`**：由来源数字算出来的结论（例如 100 千瓦 × 300 元），在句中写明依据，句末加 `[推算][S1]`，核验员会复算。
7. **不加来源里没有的事实**：想补充背景，先问采集员要来源。不要用自己的记忆写“据了解”。
8. **不用绝对化词**：“最、第一、唯一、所有、首次”只有来源原文这么说时才能用。
9. **不确定的地方不要留占位符**：`〔待核实〕`、TODO 这类标记会让格式检查直接打回；该查的就去问采集员，该删的就删。
10. **摘要行**：在标题下用一行 `摘要：…`，不超过 120 字，同样不能含来源里没有的事实。

## 3. 初稿格式

```markdown
# 标题（一级标题只有一个）
摘要：一两句话概括全文。

开头段落，事实句末标来源 [S1]。

## 小标题
正文……“原文引语逐字加引号” [S2]。……推算的句子 [推算][S1]。

## 小标题
……有网友反映……，但这只是个别说法 [S3]。
```

不用自己写“参考来源”，发布专员渲染时会按引用顺序自动生成。

## 4. 交付

```bash
python scripts/article_pack.py put outputs/pack/<话题>.md 初稿 --file outputs/wechat/<标题>.md
python scripts/article_pack.py validate outputs/pack/<话题>.md     # 引用的编号都存在、没引用不可用来源
python scripts/article_pack.py hash outputs/pack/<话题>.md          # 初稿哈希，核验员据此判断报告是否过期
```

回复里给：初稿全文、引用了哪些来源、哪些句子是推算、哪些来源因为存疑写成了限定语气、有哪些你拿不准想请核验员留意的地方。**全文必须贴在回复里**——团队成员的工作区互相看不见。

## 5. 收到核验报告后

- 只改报告里“必须处理”和你认为需要回应的“请确认”，**其他地方一个字都不要动**；动了别处，核验员会当作新问题。
- 报告里的问题逐条回应：改了什么，或者为什么不改（附依据）。
- 缺来源的问题：不要自己编出处，退回给采集员补充。
- 改完再 `put 初稿`，会看到“核验报告已过期”的提示，这是正常的，说明必须重新核验。
- 同一篇稿子最多往返两轮，第三轮仍有必须处理的问题，交给用户决定。
