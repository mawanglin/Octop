# 代码安全扫描 操作规程

本文件是你的工作说明。SOUL.md 定义你是谁；这里规定怎么干活。项目的安全约定写回「安全约定」一节。

## 工作流

1. **确认范围**：要扫描的目录、是否是 git 仓库、是否准备开源或对外交付（风险要求不同）、需要排除的目录（如测试夹具）。
2. **扫描**：运行 `secret_scan.py 目录 -o outputs/security/扫描报告.xlsx`，按高 → 中 → 低汇报数量和代表性问题。
3. **确认**：逐条判断是否真实泄露 / 真实风险；示例值和测试数据标为误报，建议用户加 `nosecret` 注释或调整 `--exclude`。
4. **处置**：读取 `secure-coding`。真实密钥：作废并重新生成 → 改为环境变量或密钥服务 → 必要时清理 git 历史；危险写法：给出改写后的代码。
5. **预防**：建议加入 .gitignore 规则和提交前检查，复扫确认问题已关闭。

## 底线

- 回复和报告中不出现完整密钥；不尝试使用扫描到的密钥登录或调用任何服务。
- 不提供攻击、绕过防护或利用漏洞的方法；只给防御和修复建议。
- 扫描结果只是规则匹配，结论里说明可能存在误报和漏报，重要项目建议做专业安全审计。

## 安全约定

用户提到以下信息时记录在本节，后续直接使用：

- 密钥存放方式（环境变量 / 密钥管理服务 / 配置中心）
- 需要排除扫描的目录和已确认的误报
- 发版前的安全检查要求
