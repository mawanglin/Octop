# 难开口的话

## 1. 通用结构

**共情 / 肯定 → 事实与立场 → 理由（简短）→ 替代方案或下一步**

- 事实和立场要清楚，不要绕到对方看不懂；
- 理由一两句即可，解释越多越像找借口；
- 尽量给替代方案，让对方有路可走；
- 对事不对人，不用"你总是""你应该"。

## 2. 场景模板

| 场景 | 写法要点 | 示例 |
|------|----------|------|
| 婉拒 | 感谢 → 明确说不 → 原因一句 → 替代方案 | "谢谢你想到我。这周我在赶〔项目〕的交付，确实抽不出时间；下周三之后可以，或者我推荐〔同事〕帮你看看？" |
| 致歉 | 承认问题（具体）→ 影响 → 已采取的补救 → 防止再发生 → 不找借口 | "关于〔事项〕的延误，是我们排期失误导致的，给您添麻烦了。我们已经〔补救措施〕，并调整了〔流程〕，确保后续不再发生。" |
| 催款 | 友好提醒 → 事实（合同、金额、到期日）→ 请求具体时间 → 逐级加强 | 第一次："〔合同〕第二期款〔金额〕已于〔日期〕到期，麻烦帮忙确认下付款安排？"；第三次：说明合同约定的逾期责任 |
| 指出错误 | 先肯定 → 具体指出（数据/位置）→ 影响 → 建议改法 → 留余地 | "报告整体很清楚，第 3 页的 Q3 营收和财务数据对不上（4.2 亿 vs 4.0 亿），可能是口径不同，麻烦核对下？" |
| 拒绝加需求 | 理解需求价值 → 说明当前约束（时间、资源）→ 给选项（延期 / 换掉另一需求 / 下期做） | "这个需求很有价值。现在加入会影响〔日期〕上线，有两个选择：①下一期做；②替换掉〔需求 X〕。您倾向哪个？" |
| 坏消息通知 | 开门见山 → 原因（简短、真实）→ 影响 → 补救方案 → 联系人 | "很抱歉通知您，〔项目〕交付将从〔日期〕延至〔日期〕，原因是〔……〕。为减少影响，我们〔补救〕。" |
| 投诉回复 | 感谢反馈 → 共情 → 不争辩 → 说明调查结果和处理 → 补偿（如授权）→ 后续联系 | 补偿方案必须由用户确认，不擅自承诺 |
| 提加薪/资源 | 用成果说话 → 市场或岗位对比 → 具体诉求 → 开放讨论 | 列出可量化的成果和新增职责，诉求具体到数字或资源 |

## 3. 注意

- 涉及法律责任（事故、合同违约、人事处理）的措辞保持中性，不主动认定责任，建议用户请法务或 HR 审阅；
- 对外道歉和补偿以用户授权为准；
- 给两个强度的版本（温和 / 坚定），由用户选择。
