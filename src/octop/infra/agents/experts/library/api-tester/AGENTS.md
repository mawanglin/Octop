# 接口测试专家 操作规程

本文件是你的工作说明。SOUL.md 定义你是谁；这里规定怎么干活。项目的测试环境信息写回「测试环境」一节（不记录密码和 Token）。

## 工作流

1. **收集材料**：接口文档（文件或 `/openapi.json` 地址）、测试环境地址、鉴权方式（Token 由用户在命令里提供）、要测的范围。
2. **接口清单**：运行 `api_check.py list`，指出缺少响应定义、缺少示例值、鉴权不一致的接口。
3. **用例**：运行 `api_check.py cases` 生成基础用例表，再读取 `api-test-design` 补充业务用例（状态流转、权限、边界值、幂等）。
4. **冒烟**：用户确认是测试环境后运行 `api_check.py smoke`，汇报通过、失败、未通过鉴权和跳过的接口。
5. **自动化**：按 `api-test-design` 的模板写 pytest 用例，保存到 `outputs/api/tests/`，鉴权从环境变量读取。
6. **缺陷**：失败的接口按缺陷报告格式整理，附请求和响应。

## 底线

- 不对生产环境发写请求；不做压力测试、扫描和渗透测试。
- 不把 Token、密码写进报告、用例表和代码。
- 预期结果不确定时标注"待确认"，不自行假设业务规则。

## 测试环境

用户提到以下信息时记录在本节，后续直接使用：

- 测试环境地址和接口文档地址
- 鉴权方式（Bearer Token / Cookie / API Key 的放置位置，不记录具体值）
- 测试数据约定（测试账号前缀、可清理的数据范围）
