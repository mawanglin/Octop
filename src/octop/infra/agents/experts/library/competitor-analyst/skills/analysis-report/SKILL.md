# 竞品分析报告

> `scripts/` 和 `references/` 路径相对于本技能目录；完整示例：`references/example-report.md`（产品和数据为虚构，演示结构与写法）。

## 1. 报告类型

| 类型 | 篇幅 | 结构 |
|------|------|------|
| 一页速览 | 500–1000 字 | 结论 3 条 → 概览表 → 建议 |
| 深度分析 | 3000–8000 字 | 核心结论 → 范围与方法 → 竞品概览 → 分维度对比 → SWOT / 定位 → 建议 → 来源 |
| 功能专项 | 1500–3000 字 | 结论 → 功能矩阵 → 体验走查（截图、步骤数）→ 用户评价 → 建议 |
| 定价专项 | 1500–3000 字 | 结论 → 定价对比表（统一口径）→ 套餐和付费点 → 价格策略建议 |
| 动态监控 | 每期 500–1500 字 | 本期要点 → 各竞品动态（版本、价格、融资、人事、营销）→ 影响判断 → 需要跟进的事 |

## 2. 写作标准

1. **结论先行**：第一节就是 3–5 条核心结论，每条是"判断 + 关键证据"，让只读第一节的人也能做决策；
2. **每个数字有来源**：用 `[1]` 角标对应文末"信息来源"，或在表格下写"来源：……，获取于 ××"；
3. **写明时间**：标题区写"数据截至 ×× 年 ×× 月 ×× 日"，价格、版本、评分都会变；
4. **事实和推断分开**：推断写"推测 / 预计"并给依据；用户评论写"用户反馈"而不是事实；
5. **对比而不是罗列**：每节都要回答"和我方相比意味着什么"；
6. **建议可执行**：至少 3 条，每条写做什么、对应哪条结论、优先级，能量化的写目标；
7. **说明局限**：样本、时间、实测环境、没拿到的数据；
8. **不贬低、不臆测**：客观描述竞品，不做无依据的负面评价；不使用未公开的内部信息。

## 3. 表格和图表

- 概览表：产品、定位、人群、规模指标、价格、最近更新；
- 功能矩阵：用 ✓ / ✗ / 部分，标注版本和日期；
- 评分雷达图和排名柱状图：用 `competitive-matrix` 生成的 Excel 图表，在 Word 里引用；
- 截图：注明产品、页面、版本和获取日期。

## 4. 检查和导出

```bash
python scripts/report_check.py outputs/竞品/报告.md --competitors 速笔,云签
python scripts/docx_build.py outputs/竞品/报告.md -o outputs/竞品/报告.docx --style report
```

- `report_check.py` 有需要补充的地方时退出码为 3；"逐段提示"逐条确认：补来源、改写成有依据的表述，或确认无误后保留；
- 报告开头的 front matter 写 `副标题` 和 `署名行`（见示例），导出 Word 时用作封面信息；
- 需要汇报 PPT 时，把核心结论、概览表和雷达图交给「PPT 设计专家」。
