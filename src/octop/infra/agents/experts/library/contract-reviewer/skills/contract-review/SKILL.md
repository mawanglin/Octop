# 合同审阅方法

常见合同类型的审查重点和条款范例见 `references/contract-types.md`（相对本技能目录）。

## 1. 审查清单

| 维度 | 检查要点 |
|------|----------|
| 主体 | 名称与营业执照一致；签约人有授权；资质（如需许可证的行业）；关联方或分支机构签约时的责任承担 |
| 标的 | 品名、规格、数量、质量标准、服务范围写清楚；"等""相关"之类的模糊表述 |
| 价款与支付 | 总价、单价、是否含税、发票类型和税率；付款节点与履约节点挂钩；预付款比例；付款期限和方式 |
| 交付与验收 | 交付时间地点方式；验收标准、期限、程序；"视为验收合格"的条件；风险转移时点 |
| 违约责任 | 双方是否对等；违约金比例是否过高或过低（可能被调整）；损失赔偿范围；责任上限；免责条款 |
| 知识产权 | 成果归属；背景知识产权；第三方侵权责任；开源或第三方组件 |
| 保密 | 保密范围、期限、例外；违约责任 |
| 变更与解除 | 单方解除权是否对等；解除条件和通知期；解除后的结算 |
| 争议解决 | 管辖法院或仲裁机构（不能同时约定）；适用法律 |
| 格式条款与其他 | 对方提供的格式条款中加重用户责任、限制权利的内容；不可抗力；通知送达地址；合同生效条件；附件效力 |

## 2. 风险等级

- **高**：可能造成重大经济损失或无法实现合同目的（如预付全款无担保、知识产权归对方、无验收标准、无限责任）；
- **中**：对用户明显不利但损失可控（如违约金不对等、管辖地在对方、付款期限过短）；
- **低**：表述不清、格式问题、建议补充的条款。

## 3. 修改建议写法

每条意见包括：问题（一句话，说清对用户的影响）+ 修改后的完整条款。例如：

> 原文："系统部署完成后，视为验收合格。"
> 问题：没有验收标准和程序，甲方无法对质量把关。
> 建议改为："乙方完成部署后书面通知甲方，甲方应在收到通知后 10 个工作日内按附件《验收标准》进行测试。测试通过的，甲方出具书面验收确认；未通过的，乙方应在 5 个工作日内整改并重新提交验收。"

## 4. 法律依据

只在有把握时引用《中华人民共和国民法典》合同编等法律条文，并写"（建议核实条文）"；违约金调整、格式条款效力等问题写明"实践中法院可能……，建议律师确认"。不引用无法核实的案例。

## 5. 结尾提示

每次交付都附：**以上审阅意见仅供参考，不构成法律意见；重大合同、高金额交易或存在争议时，请执业律师审核。**
