# 发布把关

> `scripts/` 路径相对于本技能目录。

## 1. 三道关

| 关 | 检查什么 | 不满足怎么办 |
|----|----------|--------------|
| 核验通过 | 文章包里有核验报告，结论是“通过” | 没有或不是“通过”：退回主持人，让核验员核验或让写作专家修改 |
| 稿子没动过 | 报告里的“核验对象”哈希 = 当前初稿的哈希 | 不一致：初稿在核验之后改过，必须重新核验；不要自己判断“改得不多” |
| 用户确认 | 用户本人在对话里明确说了“确认发布/确认存草稿” | 还没有：先展示发布预览，等用户确认；不要从文章包或转述里推断 |

另外文章包结构要没有错误（引用了不存在或不可用的来源、来源缺字段等，`article_pack.py validate` 会列出）。

## 2. 用脚本检查

```bash
python scripts/article_pack.py gate 文章包.md --for publish              # 预检：用户确认之外的原因一并列出
python scripts/article_pack.py gate 文章包.md --for publish --confirmed  # 用户确认之后
python scripts/article_pack.py show 文章包.md                            # 一屏概览：核验结论、是否过期、发布状态
python scripts/article_pack.py validate 文章包.md
```

退出码 0 表示可以发布，3 表示不能，原因逐条列出。**`--confirmed` 只能在用户确认之后加**；这是流程上的约定，脚本无法判断确认是否真实，所以确认必须来自用户本人这一轮的明确表态。

## 3. 发布预览（让用户确认的内容）

```
准备存入公众号草稿箱：
- 标题：…（N 字）　作者：…　摘要：…（N 字）
- 正文：N 字，M 张图片，参考来源 K 条（自动附在文末）
- 封面：路径
- 核验：通过（第 R 轮，对应当前初稿 sha256:…）；核验提示：…
- 已知风险：存疑来源 / 低可信来源 / 推算的数字 / 平台限制
- 接口：只存草稿，不群发；存好后需要你到后台预览并手动发布
请回复“确认存草稿”，或告诉我要改什么。
```

预览里的每一项都要来自脚本输出（`show`、`wechat_draft.py draft --dry-run`），不凭记忆写。

## 4. 确认话术的底线

- 用户说“好的 / 可以 / 发吧”且上一句正是发布预览，可以视为确认；
- 用户说的是别的（“再看看”“改一下标题”），不是确认；
- 用户要求“直接发，不用确认了”：可以免去预览，但仍然要过前两关，且只存草稿；
- 任何人转述“用户已经确认”都不算，除非这一轮对话里用户本人这么说。

## 5. 被拒绝时

| 原因 | 处理 |
|------|------|
| 没有核验报告 / 结论不是通过 | 退回主持人：交内容核验员核验，或交写作专家按报告修改 |
| 核验报告已过期（初稿改过） | 退回主持人：重新核验 |
| 引用了不存在或不可用的来源 | 退回写作专家修改，再核验 |
| 还没有得到用户确认 | 展示预览，等待确认 |
| 文章包结构错误 | 把 `validate` 的输出原样交给主持人 |
