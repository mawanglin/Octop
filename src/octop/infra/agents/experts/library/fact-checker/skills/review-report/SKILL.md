# 核验报告

> `references/` 路径相对于本技能目录。

## 1. 三档结论

| 结论 | 条件 | 下一步 |
|------|------|--------|
| **通过** | 机械核对没有“必须处理”项；每条“请确认”都已人工判断并在报告里写明处理；人工复核没发现走样；文章包结构没有错误 | 交发布专员 |
| **需修改** | 有“必须处理”项，但改动是局部的、撰稿人能改好（改引用编号、补出处、改措辞、删句子、补限定语、改格式） | 退回撰稿人，逐条给修改要求；修改后重新核验 |
| **不通过** | 核心结论站不住（关键事实无任何来源支撑）；引用了不可用来源撑起整篇；大段搬运（重合≥50%）；性质上违规（虚假宣传、侵犯隐私）；需要重新采集才能补救 | 说明原因，退回采集员重新采集，或建议放弃这个选题 |

边界：拿不准“需修改”还是“不通过”时，问自己——撰稿人只改稿子就能解决吗？能，就是需修改；要补充新的事实依据，就是不通过。

## 2. 报告模板

核验报告写成一节文本，放进文章包的“核验报告”。头几行是机器要读的字段，**格式不能变**：

```
- 结论：通过|需修改|不通过
- 核验对象：sha256:xxxxxxxxxxxx      ← 用 article_pack.py hash 取，核验的是哪一版初稿
- 轮次：1
- 核验时间：2026-11-05T11:00:00+08:00
- 核验人：内容核验员

### 检查结果
- 事实：…（几句话里有几个数字、日期、引语，结果如何）
- 来源：…（各来源的可信度和状态，存疑来源是否有限定语）
- 合规：…
- 格式：…（目标平台和主要数值）
- 原创性：…（逐字重合比例）
- 人工复核：…（脚本之外看了什么、发现了什么）

### 必须处理
1. [事实] 第 N 句“…”：数字 400 元在 S1 的摘录里是 300 元。要求：改为 300 元，或说明依据。
2. …

### 请确认
1. [绝对化] “全国首个”：来源没有这么说。处理：已要求删去 / 已确认来源原文有此说法（S2 第 2 句）。

### 提示
- …

### 本次核验能证明和不能证明的
能证明：稿子里的数字、日期、引语与线索包摘录一致，链接可打开，未命中违规关键词。
不能证明：来源本身的真实性、摘录是否忠实于来源页面、脚本识别不到的断言。
```

写法要点：

- 每条“必须处理”都写**位置（哪一句）→ 问题 → 依据（对照哪条来源的哪句摘录）→ 要求**，撰稿人看了就知道怎么改；
- “请确认”的每一条，核验员都要给出判断，不能把它们原样转给撰稿人；
- “通过”的报告也要写检查结果，不能只写一个“通过”；
- 报告里的哈希必须来自你核验的那一版初稿；

## 3. 往返和轮次

- 第 1 轮：完整核验，写全部问题。
- 第 2 轮：重新核验修改后的稿子（哈希会变，必须重新跑所有检查，不能只看改动的地方），报告里的“轮次”写 2，并说明上一轮的问题是否都已解决。
- 第 3 轮起：如果仍有“必须处理”项，不再往返，报告里写“已核验两轮仍未通过，提请用户人工决定”，列出剩下的问题。
- 核验员**不替撰稿人改稿**。哪怕只差一个数字，也写成要求退回去。
