# 照片库规范

## 1. 推荐结构

```
照片/
├── 2024/
│   ├── 2024-05/
│   │   ├── 20240512_143005.jpg
│   │   ├── 20240512_143005.mov      ← 实况照片的视频部分
│   │   └── 20240601_101010.mp4
├── 截图/2024/2024-05/               ← --split-sources
├── 微信图片/2024/2024-05/
└── _重复文件待确认/
```

按"年/年-月"归档最通用：文件夹数量适中，在任何文件管理器里都好找。旅行、活动等主题相册建议用相册软件的"相册"功能管理，而不是移动文件，这样一张照片可以同时属于多个相册。

## 2. 日期来源的可靠性

| 来源 | 可靠性 | 说明 |
|------|--------|------|
| EXIF 拍摄时间 | 高 | 相机和手机拍摄时写入；修图软件导出时可能被清除 |
| 文件名 | 较高 | 手机相机、截图、微信保存的文件名带有日期 |
| 文件修改时间 | 低 | 复制、下载、同步都可能改变它；按它归档的照片要抽查 |

## 3. 特殊文件

- **实况照片**（iPhone Live Photo）：`IMG_1234.HEIC` + `IMG_1234.MOV` 必须放在一起、同名，相册软件才能识别为实况照片；整理时自动跟随。
- **RAW + JPG**：同名的 `.CR3/.NEF/.ARW` 等 RAW 原片跟随 JPG（或 HEIC）一起移动、改名，保持成对；没有对应 JPG 的 RAW 文件当前环境读不了 EXIF，会按文件名或修改时间归档。
- **截图、微信图片**：信息价值和照片不同，建议单独归档，方便日后批量清理。
- **编辑记录**：`.AAE`（iPhone）、`.XMP`（Lightroom 等）随照片移动。

## 4. 相册软件兼容

飞牛相册、群晖 Photos、Immich、PhotoPrism 都会读取 EXIF 和文件时间来排时间线，目录结构不影响时间线；但部分软件的相册、人物标注、收藏记录与文件路径绑定，移动后可能需要重新扫描或丢失这些信息。整理前让用户确认，必要时先在软件里导出相册信息，或只整理尚未导入的新照片。

## 5. 常见问题

| 问题 | 处理 |
|------|------|
| 一批照片都落在同一天 | 它们没有 EXIF 也没有带日期的文件名，按修改时间归档了（通常是拷贝日期）；先单独放一边，人工确认日期 |
| 照片时间差 8 小时 | 时区问题：毫秒时间戳按服务器时区换算；EXIF 时间是相机本地时间 |
| 同一张照片有好几份 | 多次备份或多设备同步；先查重 |
| HEIC 无法识别日期 | 当前环境无法读取 HEIC 的 EXIF，按文件名或修改时间判断；iPhone 原始文件名通常不带日期，建议用户导出时选择"最兼容"格式或在相册软件中处理 |
| 整理后手机又把照片备份了一遍 | 手机备份软件按路径判断是否已备份；整理前暂停自动备份，或只整理备份目录之外的副本 |
