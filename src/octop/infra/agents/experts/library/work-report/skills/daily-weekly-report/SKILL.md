# 日报与周报

## 周报模板（默认）

```markdown
# 周报｜〔姓名/团队〕｜〔2026.10.13–10.17〕

**本周要点：**〔一句话：最重要的 1–2 个结果〕

## 本周完成
1. 〔事项〕：〔结果〕，〔数据/对比〕
2. ……

## 进行中
- 〔事项〕：进度〔x%/阶段〕，预计〔日期〕完成

## 问题与风险
- 〔问题〕→ 〔已采取的措施 / 需要谁在什么时间前提供什么支持〕

## 下周计划
1. 〔事项〕：〔可检查的目标〕，〔截止时间〕
```

规则：
- "本周完成"按重要性排序，不按时间顺序；最多 5–7 条，次要事项合并成"其他：……"。
- "问题与风险"没有就写"无"，不要硬凑；有问题必须带措施或求助对象。
- "下周计划"每条都能在下周五被检查"做没做到"。
- 给高层看的周报只保留"本周要点 + 关键数据 + 需决策事项"，控制在 5 行内。

## 日报模板

```markdown
**〔日期〕日报**
- 完成：〔事项 + 结果〕
- 进行中：〔事项 + 进度〕
- 明日：〔1–3 件事〕
- 需协调：〔无 / 具体事项和对象〕
```

日报控制在 5–8 行，能在手机上一屏看完。

## 从素材提炼的方法

1. 把素材逐条改写成"动作 + 结果"，删掉没有结果的过程描述（"开了 3 个会"→ 只保留会上定下的结论）。
2. 找数据：素材里的数字、链接、版本号、客户名称都是可用的证据；没有数据时用可验证的结果（"已上线""已签约""已提交评审"）。
3. 合并同类：同一项目的多条记录合成一条，写最新状态。
4. 识别风险：素材里出现"延期""卡住""等待""依赖"的都检查是否需要写入问题与风险。

## 交给定时任务

用户希望每周自动生成时，建议创建定时任务：每周五下午读取本周记录文件（如 `notes/` 目录或任务清单）生成周报草稿，先发给用户确认，不自动发送给他人。
