# 提示词体检

> `scripts/`、`references/` 路径相对于本技能目录。

## 1. 运行

先把提示词存成文件（建议 `outputs/prompts/名称-v1.md`），再检查：

```bash
python scripts/prompt_lint.py lint outputs/prompts/客服分类-v1.md
python scripts/prompt_lint.py lint prompt.md --json          # 给程序处理
python scripts/prompt_lint.py lint template.md --template    # 这是模板，占位符不算问题
python scripts/prompt_lint.py lint prompt.md --strict        # “建议修改”也让退出码变 3
cat prompt.md | python scripts/prompt_lint.py lint -         # 从标准输入读
```

退出码：0 没有“必须处理”，3 有“必须处理”（`--strict` 时“建议修改”也算），1 输入错误。

## 2. 检查项

| 编号 | 级别 | 查什么 | 为什么要紧 |
|------|------|--------|-----------|
| P1 | 必须处理 | 密钥、Token、私钥、密码写在了提示词里（只显示前 4 位） | 会被日志、缓存和模型输出带出去 |
| P2 | 必须处理 | `___`、`XXX`、`TODO`、`待填`、`［…］` 等没填的占位符 | 会被模型当正文 |
| P3 | 建议修改 | 没写输出格式；或要求 JSON / 表格却没给字段 | 输出每次长得不一样，程序解析会失败 |
| P4 | 建议修改 | 名为 input / text / query / 文档 / 反馈 的变量没有放进标记或代码块 | 输入里的“忽略以上指令”会生效 |
| P5 | 建议修改 / 提示 | 尽量、适当、较好、高质量、相关、等等…… | 没有标准，模型和你理解不同 |
| P6 | 请确认 | 简短 vs 详尽、只输出结果 vs 要解释、严格照做 vs 自由发挥、中文 vs 英文 | 可能互相矛盾，也可能只是适用范围不同 |
| P7 | 建议修改 | 清单里一半以上是“不要……” | 只说不要，模型仍不知道该怎么做 |
| P8 | 建议修改 | 必须、绝对、严禁、IMPORTANT 等强调词 8 处以上 | 强调太多，模型过度执行 |
| P9 | 建议修改 / 提示 | 找不到任务句；内容过短；超过约 3000 / 8000 tokens | 任务不明；长提示词里的指令容易被稀释 |
| P10 | 提示 | 角色吹嘘、重复指令、只有 1 个示例、要求结构化输出却没示例、基于资料作答却没写“没有时怎么办” | 影响稳定性，不一定要改 |

另外输出会列出**结构**一栏（角色、任务、背景、约束、输出格式、示例哪些出现了）和**变量**清单，帮你一眼看出缺什么。角色和背景不是每个提示词都要有。

## 3. 读结果

- **按级别处理**：必须处理的先改；建议修改的逐条看，有理由不改就说明；请确认的要和用户核对；提示项选做。
- **脚本是关键词和格式检查**，会有误报和漏报。例如 P4 只认变量名里带 input、text、文档这类词的变量；P6 看到两类词同时出现就提醒，不判断是否真的冲突。每一条都要读上下文再下结论。
- **脚本看不到的**：任务本身是不是对的、规则和示例是否一致、业务术语是否用对、模型会不会照做。这些要靠人读和 `prompt-eval` 的用例测试。
- 体检通过不等于提示词好，只表示没有踩到常见的坑。

## 4. 给用户的反馈方式

1. 先说结论：有几条必须处理、几条建议修改；
2. 逐条说明**问题 → 为什么要紧 → 怎么改**，引用行号和原文；
3. 给出改写后的完整提示词，保存为新版本（`-v2`），再跑一次体检确认问题消失；
4. 提醒：改完要用 `prompt-eval` 在真实输入上测，别只看体检结果。

## 5. 参考

`references/example-weak.md` 是一份典型的问题提示词（吹嘘的角色、模糊词、一串“不要”、输入没隔离、格式要求矛盾、占位符没填），`references/example-strong.md` 是改写后的版本，可以对照着给用户讲。
