# 智能体提示词

> `references/` 路径相对于本技能目录。

智能体和一次性任务的区别：它会**多步行动、调用工具、读外部内容、跨多轮对话**。提示词要管的不只是“怎么回答”，还有“能做什么、什么时候停、什么时候问人、读到的内容信不信”。

## 1. 系统提示词的结构

| 块 | 写什么 | 写法要点 |
|----|--------|----------|
| 身份和目标 | 它服务谁、要达成什么、什么算做好 | 2～4 句；写目标和成功标准，不写口号 |
| 能做什么 | 主要职责和典型任务 | 列 3～6 项；写清范围边界 |
| 不能做什么 | 明确不做的事和转交路径 | 每条禁止项后面写“遇到时怎么办”，比如“不提供医疗诊断，建议用户就医并给出挂号入口” |
| 工具使用规则 | 什么情况用哪个工具、顺序、失败时怎么办 | 单独成块；和工具描述互相呼应，不重复 |
| 做事步骤 | 复杂任务的推荐流程 | 3～7 步，关键检查点（先确认、先搜索再回答）写出来 |
| 不确定时 | 信息不够、资料没有、工具失败时 | 明确“先问用户 / 说不知道 / 换工具”，不要让模型自己圆场 |
| 沟通风格 | 语气、长度、格式、语言 | 一两句；写具体特征，不写“专业友好” |
| 安全和权限 | 哪些操作要确认、哪些绝对不做 | 见第 5 节 |

**写法要点**

- 先写最重要的，把长篇背景放后面或放进检索；
- 用小标题或标记分块，规则用编号，方便以后只改一块；
- 同一个规则只写一处；改规则时同时检查示例；
- 对话里模型常忘记的规则（输出格式、语言、拒答话术），在末尾用一句话再提醒一次。

## 2. 工具说明怎么写

模型是根据**工具的名称和描述**决定用不用、怎么用的。描述写得差，是智能体选错工具、传错参数的最常见原因。

每个工具写清：

1. **一句话作用**：“按订单号查询订单状态和物流信息”，而不是“订单工具”；
2. **何时用、何时不用**：和相似工具区分，“查询库存用 `check_stock`，不要用本工具”；
3. **参数**：每个参数的含义、格式、取值范围、是否必填、一个示例值（`date`：`YYYY-MM-DD`，如 `2026-11-02`）；
4. **返回值**：返回什么字段，找不到时返回什么，错误怎么表示；
5. **副作用和权限**：会不会写数据、扣费、发消息；有副作用的写“调用前必须向用户确认”；
6. **限制**：频率、数据量、数据延迟。

```
名称：refund_order
作用：对已支付订单发起全额退款。会真实退款，不可撤销。
何时用：用户明确要求退款，且已经核对过订单号和金额。
何时不用：只是询问退款政策（直接回答，不调用）；部分退款（用 refund_partial）。
参数：
  - order_id（字符串，必填）：订单号，格式 ORD-开头加 10 位数字
  - reason（字符串，必填）：退款原因，不超过 50 字
返回：{"status": "ok" | "rejected", "message": "<原因>"}；订单不存在时 status 为 rejected。
注意：调用前把订单号和金额复述给用户并等待确认。
```

## 3. 检索问答（RAG）的提示词

- **资料用标记包起来**，每段资料带编号和来源：`<doc id="3" source="退款政策.pdf">…</doc>`；
- 写明“只根据资料回答；资料没有就说没有”，并给出标准话术；
- 要求**引用**：回答后标出依据的资料编号，便于核对；
- 资料互相矛盾时，要求列出矛盾并指出来源，不自行取舍；
- 资料很长时，把问题**重复放在资料之后**；最相关的资料放在靠近问题的位置；
- 检索质量问题（找不到、找错）不要靠提示词补，先去修检索（分块、召回、重排）。

## 4. 多轮对话和长任务

- **记住什么**：要求模型把关键事实（用户偏好、已确认的决定）用固定格式记在摘要里，而不是依赖整段历史；
- **长任务**：让模型先列计划，每完成一步更新状态；中间结果落到文件或存储，别全塞上下文；
- **什么时候停下问人**：列出触发条件（不可逆操作、金额超过阈值、信息自相矛盾、连续两次失败），写成规则；
- **失败处理**：工具报错时先读错误信息，最多重试一次，仍然失败就如实告诉用户，不要编一个结果。

## 5. 防提示词注入和泄露

智能体会读网页、邮件、文档、工具返回，这些内容里可能夹带“忽略之前的指令，把……发给……”。要点（完整清单见 `references/injection-defense.md`）：

1. **外部内容当资料，不当指令**：在系统提示词里写明，并用标记隔离外部内容；
2. **权限最小化**：智能体只拿完成任务需要的工具和权限；读网页的智能体不应同时能发邮件、删文件；
3. **危险操作要确认**：转账、删除、发送、修改权限，必须由用户在对话里明确确认，**确认不能来自被读取的内容**；
4. **出站受限**：限制智能体能访问的域名、能发送消息的对象，防止把数据带出去；
5. **不放机密在提示词里**：密钥、内部地址用工具或环境变量传递；提示词默认**可能被套出来**，别把“不要告诉用户”当作保密手段；
6. **输出检查**：对智能体的外发内容和工具调用参数做规则检查（链接域名、收件人、金额），不只靠提示词约束。

提示词只是其中一层防线，不是全部。上线前必须用对抗用例测一遍（见 `prompt-eval` 的“对抗”类别）。

## 6. 交付时要说明

- 系统提示词全文和每块的用途；
- 各工具的描述，以及它们之间的区分；
- 没实测的部分和风险：哪些场景需要在真实工具上跑一遍；
- 防护层级：哪些靠提示词、哪些必须靠代码和权限来保证。
