# 架构评审清单

逐项过一遍。能从代码和扫描结果确认的先确认，确认不了的问用户，问不到的写进“待确认”。

## 1. 边界和职责

- [ ] 每个模块/服务一句话说得清职责吗？有没有“万能的 utils / common / manager”？
- [ ] 依赖方向一致吗？（`arch_scan.py` 看循环依赖、双向依赖、分层违规）
- [ ] 业务规则在领域/业务层，还是散落在接口层、前端、数据库触发器里？
- [ ] 有没有“上帝类/文件”（超大文件，承担多个职责）？
- [ ] 外部系统通过适配层接入，还是业务代码到处直接调用第三方 SDK？
- [ ] 共享库里是不是塞了业务逻辑，导致改一处影响所有人？

## 2. 数据

- [ ] 每份数据有明确的归属服务吗？有没有多个服务直接读写同一张表？
- [ ] 核心表的主键、唯一约束、索引、外键合理吗？大表有没有归档和清理策略？
- [ ] 一致性要求是什么？跨服务/跨存储的更新有没有补偿和对账？
- [ ] 数据库迁移可回滚吗？迁移和代码发布的顺序有没有写清楚？
- [ ] 敏感数据（个人信息、凭证、支付）是否分级、加密、限制访问、有审计？
- [ ] 备份有没有定期**恢复演练**过？恢复时间和数据丢失量（RTO / RPO）是多少？

## 3. 接口

- [ ] 接口有版本和兼容策略吗？改字段会不会悄悄破坏调用方？
- [ ] 错误码和错误结构统一吗？调用方能区分“可重试”和“不可重试”吗？
- [ ] 写接口幂等吗？（重复请求、重试、消息重复投递）
- [ ] 有分页、限流、超时、请求大小限制吗？
- [ ] 接口文档和实现一致吗？有没有自动生成或校验？

## 4. 可靠性

- [ ] 有单点吗？（单实例应用、单库、单消息节点、单个定时任务机器）
- [ ] 每个外部调用都有超时、重试（带退避）、熔断或降级吗？
- [ ] 一个下游变慢会不会拖垮整个系统？（线程/连接池耗尽、重试风暴）
- [ ] 异步任务失败会怎样？有重试、死信、告警、人工补偿吗？
- [ ] 定时任务多实例会不会重复执行？有没有分布式锁或单实例保证？
- [ ] 有没有演练过：数据库主从切换、机器宕机、依赖服务不可用？

## 5. 性能和容量

- [ ] 有没有 N+1 查询、无索引的大表查询、循环里调外部接口？
- [ ] 同步调用链有多长？关键路径上有没有可以异步的慢操作？
- [ ] 缓存的失效策略、穿透、雪崩有没有考虑？缓存挂了数据库扛得住吗？
- [ ] 做过容量估算和压测吗？当前余量多少？（`capacity.py`）
- [ ] 有资源上限吗？（内存、连接数、文件句柄、队列长度、上传大小）

## 6. 安全

- [ ] 认证和授权是否在服务端统一检查？有没有只靠前端隐藏按钮的？
- [ ] 多租户/多用户的数据隔离是在查询层强制的，还是靠各处自觉加条件？
- [ ] 密钥和配置放在哪？有没有写进代码、镜像、日志？
- [ ] 外部输入（参数、文件、Webhook、模板）都校验了吗？有没有注入、SSRF、路径穿越风险？
- [ ] 依赖有没有已知漏洞？有没有定期更新的机制？
- [ ] 日志里有没有敏感信息？审计日志能不能追溯到人和操作？

## 7. 可观测

- [ ] 日志结构化吗？有请求 ID 贯穿多个服务吗？
- [ ] 有核心业务指标和系统指标吗？（请求量、错误率、延迟分位数、队列堆积、资源使用）
- [ ] 告警指向可执行的动作吗？有没有半夜总是误报、没人理的告警？
- [ ] 出问题时，能在 10 分钟内判断是哪个组件的问题吗？
- [ ] 有运行手册吗？（常见故障、重启、回滚、联系人）

## 8. 部署和发布

- [ ] 构建和部署自动化吗？环境之间配置一致吗？
- [ ] 发布能灰度、能秒级回滚吗？回滚演练过吗？
- [ ] 数据库变更和代码发布的兼容策略是什么？（先加字段、再改代码、最后删旧字段）
- [ ] 有没有特性开关？线上能不能紧急关闭某个功能？
- [ ] 基础设施是代码化管理的吗？还是有人手工改过的“雪花服务器”？

## 9. 可维护性

- [ ] 新人能多快跑起来并改动？README、本地开发步骤还有效吗？
- [ ] 核心业务有自动化测试吗？测试稳定吗？CI 要跑多久？
- [ ] 依赖版本管理有序吗？有没有被长期不升级的老版本卡住？
- [ ] 有架构图和决策记录吗？和代码一致吗？
- [ ] 技术债有登记和偿还计划吗？

## 10. 评审结论的写法

按影响分级：

| 级别 | 含义 | 例子 |
|------|------|------|
| 高 | 会造成故障、数据丢失或安全事件，或阻碍业务发展 | 单点、无备份恢复演练、越权风险、跨服务共享表 |
| 中 | 增加维护成本或在增长后会出问题 | 循环依赖、无超时的外部调用、告警缺失 |
| 低 | 不影响当前，长期积累成债 | 命名不一致、局部重复、文档过时 |

每条问题给出：**位置 → 证据 → 影响 → 建议 → 工作量**。同级里按“改动成本从低到高”排，先做便宜又有效的。
