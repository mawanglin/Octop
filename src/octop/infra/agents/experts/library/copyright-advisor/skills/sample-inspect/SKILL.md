# 作品样本分析

> `scripts/` 路径相对于本技能目录。脚本只读，不修改样本。

## 1. 两种"读"要配合使用

| 方式 | 能看到什么 | 怎么做 |
|------|-----------|--------|
| **直接看**（模型阅读原件） | 画面内容、构图、风格、署名和水印、扫描件里的文字、手稿 | 用 `read_file` 打开图片或 PDF。需要专家使用支持看图的模型；不支持时请用户换模型，或改用下面的脚本 |
| **脚本读** | 肉眼看不到的元数据：创建/修改时间、作者、设备、软件、AI 生成参数、指纹 | 运行 `sample_inspect.py` |

分析结论要同时说明"从内容上看到了什么"和"从元数据上发现了什么"，两者矛盾时（例如画面像 AI 生成，元数据却没有痕迹）如实说明，不下定论。

## 2. 运行

```bash
python scripts/sample_inspect.py scan 样本目录 --author 张三 -o outputs/版权/样本报告.xlsx
python scripts/sample_inspect.py compare 样本目录 -o outputs/版权/比对.xlsx
python scripts/sample_inspect.py compare 疑似侵权目录 --ref 我的原作.jpg
```

- `--author`：声称的作者或单位，用来核对元数据里的作者字段；
- `compare` 不带 `--ref` 时两两比对（最多 300 个文件），带 `--ref` 时只比参照作品和其他文件；
- 图片和图片比、文字和文字比（docx / pptx / xlsx / pdf / txt / md 都按文字处理）。

## 3. 线索怎么解读

| 线索 | 含义 | 建议 |
|------|------|------|
| AI 生成痕迹 | 图片里有 Stable Diffusion / ComfyUI 等生成参数，或软件、来源类型字段标明 AI 生成 | 询问用户的创作过程；能否登记、能否主张权利取决于人的独创性投入（见 `copyright-registration`） |
| 作者不一致 | 元数据作者与声称的作者不同 | 可能是用了别人的模板、电脑用户名不同，或确实他人创作；请用户说明并准备权属证明（委托合同、职务作品约定等） |
| 作者是默认值 | `Administrator`、`python-docx` 等软件默认值 | 不能作为权属依据，也不能作为反证 |
| 修改早于创建 | 文件被复制、转存或元数据被改过 | 不作为唯一证据，结合底稿、源文件判断 |
| 没有元数据 | 平台压缩、截图、导出时被清除 | 创作时间靠原图（RAW、PSD）、创作过程文件、聊天记录、发布记录证明 |
| 扫描件 | PDF 没有文字层 | 直接用看图模型阅读，或请用户提供原始电子稿 |

元数据**可以被修改**，只能作为线索和辅助证据，不能单独证明创作时间或作者身份。

## 4. 相似度怎么解读

| 类型 | 高度相似 | 可能 / 部分相似 |
|------|----------|----------------|
| 图片（64 位哈希距离） | ≤ 10：基本是同一张图经过缩放、调色、压缩或镜像 | 11–18：构图接近，需要人工看图确认 |
| 文字（片段重合比例） | ≥ 50%：大段相同 | 15%–50%：有相同段落，检查是否属于合理引用、公有领域内容或通用表述 |

结论只用于初筛。是否构成侵权要看：原作是否具有独创性、被诉方是否有接触可能、相同部分是不是表达（而非思想、通用素材、公有领域内容），由律师或法院判断。报告里写"高度相似，建议进一步取证和咨询专业人士"，不写"构成侵权"。
