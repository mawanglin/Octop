# 软件著作权登记材料

> `scripts/` 路径相对于本技能目录。以下格式要求来自《计算机软件著作权登记办法》和登记机构的常见要求，**提交前以中国版权保护中心最新说明为准**。

## 1. 源程序鉴别材料

```bash
python scripts/softcopy_doc.py 代码目录 --name "某某智能管理系统" --version V1.0 -o outputs/软著/源程序.docx
python scripts/softcopy_doc.py 代码目录 --name "某某APP" --ext .kt,.java --exclude "*/test/*" --order 文件顺序.txt -o outputs/软著/源程序.docx
```

- 源程序不足 60 页全部提交；超过时提交前 30 页和后 30 页（连续），每页 50 行；
- 页眉"软件全称 + 版本号"必须与申请表完全一致，右侧页码；
- 入口文件（main、App、index）建议放在最前，用 `--order` 指定文件顺序；
- 只收录自己编写的代码，排除第三方库、自动生成的代码和测试数据；
- 脚本会提示疑似密码和密钥：提交的材料会被存档，务必先删除或替换；
- 生成后用 Word 打开，在页面视图下核对页数和每页行数，确认后转 PDF。

## 2. 文档鉴别材料（软件说明书）

一般提交用户手册、设计说明书等任一种文档，规则同源程序：不足 60 页全部提交，超过时前后各 30 页；每页不少于 30 行（有图的页除外），页眉同样写软件全称和版本号。说明书建议结构：

1. 引言：编写目的、软件简介、运行环境（硬件、操作系统、数据库、浏览器）；
2. 功能总览：功能结构图、主要模块说明；
3. 操作说明：按模块逐项说明，配系统截图（截图里的软件名称要与申请一致，去掉无关水印）；
4. 其他：常见问题、注意事项。

## 3. 申请表要点

| 项目 | 注意 |
|------|------|
| 软件全称 | 通常以"软件""系统""平台""APP"等结尾；全称、简称、版本号在所有材料里保持一致 |
| 版本号 | 如 V1.0；与源程序、说明书页眉一致 |
| 开发完成日期 | 不晚于申请日；与首次发表日期逻辑一致 |
| 发表状态 | 已发表填首次发表日期和地点；未发表如实填写 |
| 开发方式 | 独立开发、合作开发、委托开发、下达任务开发；后三种需提交合作或委托协议等权属证明 |
| 权利取得方式 | 原始取得或继受取得（受让、承受、继承需提交证明） |
| 硬件 / 软件环境、编程语言、源程序量 | 与实际相符，源程序量可参考脚本统计的行数 |
| 主要功能和技术特点 | 写清解决什么问题、核心功能、技术特点，避免夸大和照抄他人 |

费用、办理时限、加急服务以官方最新公告为准，必要时联网核实；提醒用户警惕"包过""加急保证下证"等不规范代理。
