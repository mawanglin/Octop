# 版权政策解读

> 法律条文要点：`references/copyright-laws.md`；新旧对比示例：`references/example-2010.md`（2010 年修正版节选）和 `references/example-2020.md`（2020 年修正版节选）；`scripts/` 和 `references/` 路径相对于本技能目录。

## 1. 先核实文件

解读前确认：文件全称、文号、发文机关、发布和施行日期、**效力层级**、**是否现行有效**（有没有被修订或废止）。

| 层级 | 例子 | 说明 |
|------|------|------|
| 法律 | 《著作权法》《民法典》 | 全国人大及其常委会制定，效力最高 |
| 行政法规 | 《著作权法实施条例》《计算机软件保护条例》《信息网络传播权保护条例》 | 国务院制定 |
| 部门规章 | 《计算机软件著作权登记办法》《作品自愿登记试行办法》 | 国家版权局等部门制定 |
| 司法解释 | 最高人民法院关于审理著作权民事纠纷案件的解释 | 法院审判直接适用 |
| 地方性法规、规章和规范性文件 | 各省市版权登记资助办法、版权产业扶持政策 | 只在本地区有效，常有申报期限 |
| 平台规则 | 平台原创保护、侵权投诉规则 | 合同性质，不是法律 |

**来源优先级**：国家法律法规数据库、国家版权局、中国版权保护中心、各省市版权局和政府官网 > 权威媒体 > 其他。用户只给了标题或转述内容时，先联网检索原文；找不到原文时明确说明"以下基于转述，未核对原文"。

## 2. 一页速读（每次先给这个）

```markdown
# 〔文件名称〕速读

- **文件**：〔发文机关〕〔文号〕，〔发布日期〕发布，〔施行日期〕起施行；效力层级〔……〕；现行有效〔是/待核实〕
- **一句话**：〔解决什么问题、主要做了什么〕
- **适用对象**：〔个人创作者 / 企业 / 软件开发者 / 平台……〕
- **核心内容**（3–5 条，注明条款号）
- **关键时间**：〔施行日、过渡期、申报期、截止日〕
- **与你相关**：〔结合用户情况说明影响和要做的事〕
- **待确认**：〔原文不明确、需咨询主管部门的问题〕
```

## 3. 逐条解读和适用自查

逐条解读用"条款 | 原文要点 | 通俗解释 | 注意事项"四列表格；判断能否享受政策时，把条件拆成清单：

| 条件 | 原文依据 | 用户情况 | 是否满足 |
|------|----------|----------|----------|
| 申请人注册地在本市 | 第三条 | 〔待用户确认〕 | 待确认 |

结论写"初步判断符合 / 不符合 / 条件不明，以主管部门审核为准"，不承诺一定能享受。

## 4. 版权资助、补贴申报清单

各地对作品登记、软件登记、版权示范单位等常有资助或奖励，政策差别大、每年调整。解读时逐项列出：

| 项目 | 内容 |
|------|------|
| 申报主体 | 个人还是单位、注册地或户籍、是否要求纳税或社保 |
| 资助对象 | 哪些作品类别、登记时间范围（如"上一年度取得证书"） |
| 标准 | 按件资助金额、单个主体年度上限、是否区分作品类别 |
| 申报时间和渠道 | 起止日期、线上系统或窗口 |
| 材料 | 申请表、登记证书、身份证明、银行账户、承诺书 |
| 限制 | 是否可与其他资助叠加、弄虚作假的追回和惩戒 |

## 5. 新旧版本对比

```bash
python scripts/text_diff.py 旧版.docx 新版.docx -o outputs/版权/对比.md --xlsx outputs/版权/对比.xlsx
python scripts/text_diff.py references/example-2010.md references/example-2020.md
```

支持 .docx / .md / .txt，按条款对齐，列出新增、删除、修改，修改处标出字词变化。脚本只比对文字，变化的含义要结合立法说明解读：哪些是实质变化（权利范围、赔偿标准、适用对象），哪些只是文字调整。

## 6. 底线

- 以原文为准，引用注明条款号；原文没有的内容不替发文机关"补充"；
- 区分原文、解读和推测，推测标明"可能""预计"；
- 联网检索的内容注明来源和日期，提醒以正式发布版本为准；
- 解读仅供参考，不构成法律意见；涉及具体纠纷建议咨询律师。
