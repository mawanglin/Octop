# 项目控制

## 1. 风险登记表

| 编号 | 风险描述（如果……就会……） | 概率 高/中/低 | 影响 高/中/低 | 应对措施 | 负责人 | 触发条件 | 状态 |
|------|--------------------------|---------------|---------------|----------|--------|----------|------|
| R1 | 如果第三方接口文档延期，联调就会推迟 | 中 | 高 | 先用 Mock 数据开发；每周确认进度 | 赵六 | 11-15 仍未拿到文档 | 跟踪中 |

应对策略：规避（改方案）、减轻（提前做、加缓冲）、转移（外包、保险）、接受（预留应急时间）。概率和影响都为"高"的每周检查。

## 2. 变更控制

1. 提出：变更内容、原因、提出人；
2. 评估：对范围、工期（用 `project-schedule` 重新排期）、成本、质量的影响；
3. 审批：由项目发起人或变更委员会决定，书面确认；
4. 执行：更新任务表、计划和沟通。没有审批的变更不进入开发。

## 3. 项目周报

```markdown
# 【项目名】周报（第 N 周，MM-DD ~ MM-DD）
**总体状态：🟢 正常 / 🟡 有风险 / 🔴 延期**　计划完成：YYYY-MM-DD（较上周 ±N 天）

## 本周完成
## 下周计划
## 进度
（关键路径任务进度、落后任务及影响——来自 gantt.py --today）
## 风险与问题
## 需要的支持 / 决策
```

状态判断：关键路径无落后为绿；有落后但在浮动或缓冲内为黄；完成日期推迟为红。

## 4. 会议

- 站会（15 分钟）：昨天完成、今天计划、遇到的阻碍；问题会后单独讨论。
- 周会（30–60 分钟）：进度、风险、变更、决策事项；会后 24 小时内发纪要。
- 里程碑评审：交付物是否满足完成标准、遗留问题清单、是否进入下一阶段。

## 5. 复盘

1. 回顾目标：最初的目标和成功标准；
2. 对比结果：实际交付、工期、质量与计划的差异（用数字）；
3. 分析原因：做得好的、可以改进的，找到可控的根本原因，不追究个人；
4. 改进行动：具体、有负责人和时间的 3 条以内行动。
