# 线索检索

> `references/` 路径相对于本技能目录。

## 1. 动手前先问清楚

| 问题 | 为什么 |
|------|--------|
| 话题的范围是什么？只要某个事件，还是整个领域的梳理？ | 范围决定检索深度和来源数量 |
| 写给谁、发在哪个平台、多长？ | 决定要多少细节、是否需要数据和案例 |
| 关心哪段时间？ | 没有时间窗口会混进过期的信息 |
| 有没有必须引用或必须回避的信息源？有没有禁区？ | 避免白做，也避免踩线 |
| 是追热点，还是常规选题？ | 热点要快但更要核实，常规选题可以更深 |

## 2. 检索方法

1. **扩展检索词**：同一件事至少用 3 组词：通用说法、官方或正式名称、当事方的原话；中英文都搜；人名、机构名、产品名、文号、日期都可以作为检索词。
2. **顺藤摸瓜**：看到“据报道、有消息称”就去找它引用的源头，直到找到最早的出处（官方公告、原始文件、论文、数据集、当事人的公开发言）。找不到源头的，本身就只能算 C 或 D。
3. **分层采集**：先一手来源，再主流媒体和权威机构的解读，再行业观点，最后才是网友讨论；后几层用来补充角度和了解舆情，不当事实依据。
4. **留出反方**：有争议的话题主动找不同立场的材料，不要只收集支持某一个结论的。
5. **记检索日志**：把用过的检索词、搜索服务和日期写进线索包的备注或交付说明，别人才能复查和补搜。

## 3. 来源分层

| 级别 | 含义 | 例子 | 怎么用 |
|------|------|------|--------|
| A | 一手来源 | 政府和机构官网公告、企业公告和财报、法院文书、论文和原始数据 | 可以直接支撑事实 |
| B | 可靠的二手来源 | 主流媒体和专业媒体的报道、权威机构解读 | 可以支撑事实，最好能和 A 互相印证 |
| C | 单一或倾向性来源 | 自媒体、行业论坛、个人博客、单一信源的报道 | 只作线索，写进稿子要加“有网友反映/据称”这类限定 |
| D | 无法核实 | 匿名爆料、截图无出处、无法追溯的转发 | 状态标“不可用”，写明原因，不进稿子 |

详细的判断细则和边界情况见 `references/source-grading.md`。

## 4. 够用标准

| 事实的重要程度 | 至少需要 |
|----------------|----------|
| 文章的核心结论、数字、时间、人名、引语 | 1 条 A 级来源，或 2 条互相独立的 B 级来源 |
| 背景和辅助说明 | 1 条 B 级来源 |
| 观点和评论 | 标明是谁说的、在哪说的；不当作事实 |
| 只有 C 级的内容 | 不作为核心事实；用的话必须限定语 |

“互相独立”指不是同一家的转载，也不是互相引用。`source_pack.py dedupe` 会把转载合并成同一条。

## 5. 热点评估

给每个候选热点打个分再决定写不写：

| 维度 | 问什么 |
|------|--------|
| 时效 | 还在发酵吗？现在写会不会已经过时？ |
| 可核实 | 关键事实有一手来源吗？还是全靠传言？ |
| 匹配 | 和账号定位、读者关心的事一致吗？ |
| 风险 | 涉及敏感话题、个人隐私、未成年人、未经证实的指控吗？ |
| 角度 | 有没有别人没讲、我们能补充的信息或视角？ |

可核实低、风险高的热点，建议不碰，并说明理由。

## 6. 处理矛盾

- 把各方的原文摘录**并排**放进线索包，写明差异在哪里（数字不同、时间不同、说法相反）；
- 优先看谁是一手、谁更新、谁有更完整的上下文；
- 实在分不出，就让撰稿人写成“A 说…，B 说…”，不要替用户选一个；
- 官方后来更正过的，以更正为准，并把更正也登记为来源。

## 7. 交付清单

- 来源数量和可信度分布（A/B/C/D 各几条，可用/存疑/不可用各几条）
- 关键事实清单，每条带来源编号
- 矛盾点和信息缺口
- 不可用素材和原因
- 建议的写作角度和不建议碰的角度
- 线索包全文（让主持人能转给撰稿人）
