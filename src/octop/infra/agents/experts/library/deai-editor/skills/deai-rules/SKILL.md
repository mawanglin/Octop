# 中文去 AI 味规则

> 规则参考了 qu-ai-wei、lieflat-less-ai-tone、Humanizer-zh 等开源项目（MIT），频率数据出自 lieflat 的语料实测，详见 `references/sources.md`。

## 0. 先选模式

| 模式 | 什么时候 | 怎么做 | 交付 |
|------|----------|--------|------|
| **清理** | 别人的稿、AI 初稿、已定稿只想去味、用户说"别改我的意思" | 只改规则明确命中的地方，其余逐字保留；拿不准就不改 | 直接交改好的全文，附改动清单 |
| **作者稿** | 用户自己的文章，想改得更像自己 | 可以下重手；缺具体材料的地方标 `[请作者补：……]`，向作者要，不替作者编；按作者声音校准（`voice-calibration`） | 默认交"红笔报告"（逐行问题 + 两种改法），用户要全文再给 |
| **新写** | 从零写公众号、汇报、文案等 | 写之前就按第 3–6 节避开，写完用 `ai_tone_check.py scan` 自检 | 交成稿 |

用户没说时：给了现成稿子默认"清理"，说"帮我改改我的文章"默认"作者稿"。

## 1. 硬边界（高于所有去味规则）

1. **信息守恒**：不新增原文没有的事实、数字、人名、机构、日期、引语、出处、因果、动机、心理活动、场景、案例；也不删观点、结论、限定和让步。"可能提升"不能改成"提升"，"部分用户"不能改成"用户"。
2. **最小改动**：一句话命中了规则，也只改解决这个问题必需的部分；不顺手润色，不替换没问题的词。
3. **结构不动**：标题层级、章节和段落顺序、列表、表格、引用、代码块、网址、路径、front matter 都不碰（序数小标题去编号除外）。
4. **笼统的背书保持笼统**："有专家认为"不能补成具体的人，也不能升格为事实。

一句话：**宁可留一点 AI 味，也不造一个假事实。** 改完必须跑 `ai_tone_check.py diff 原稿 改稿`。

## 2. 三个病根

判断一句话要不要动，回到这三条：

| 病根 | 表现 | 判据 |
|------|------|------|
| 不信任读者 | 堆总结、堆过渡、把话说满、替读者下结论 | 遮住这句总结，前文意思还在吗？在，就删 |
| 替作者占位 | 自造金句、编作者不在场的细节、替作者下斩钉截铁的判断 | 这句话是不是只有作者本人写得出？是，就删掉留空位，标 `[请作者补]` |
| 好心加戏 | 补反例、补对照、补第四项、补"翻译成人话" | 这个补充推翻主判断吗？不推翻，就删 |

## 3. 门槛（先过这一关）

- **全角标点**：中文正文里的 `, . : ; ? ! ( "` 改成全角，`--` 改 `——`，`...` 改 `……`；数字（3.14、2025-10）、英文专名、网址、代码、公式单位里的除外；
- **粗体**：去掉所有 `**` 通读一遍，论点还看得出来就全删；只留警告和长文里帮助定位的一两处；
- **惊叹号、emoji、装饰箭头、分隔线**：正文里删，作者要加让作者自己加；
- **聊天残留**：“好的，以下是……”“希望对你有帮助”“如果还有问题”“作为 AI……”——全删。

## 4. 十六条实测规则

频率为每千字（另注明的除外），"AI / 人类"来自 AI 300 篇、人类 329 篇的语料对照。脚本 `ai_tone_check.py` 的规则编号与此一致。

| 编号 | 规则 | AI / 人类 | 改法 | 例 |
|------|------|-----------|------|----|
| Z1 | 翻案腔：先立一个没人有的误解再推翻（不是……而是、并非……而是、与其说……不如说、看似……实则、你以为……其实、说到底） | 0.73 / 0.22 | 直接从正面说 | 真正的门槛不是技术，而是耐心。→ 真正的门槛是耐心。 |
| Z2 | 顿号罗列过密：一个分句里连列三项以上 | 3.21 / 1.78 | 能概括就概括；必须保留三项时换其中一项的说法 | 无论是初创公司、中型企业还是大型集团都适用。→ 各种规模的公司都能用。 |
| Z3 | 相邻句结构同款：相邻句逗号数、长度、成分顺序都一样 | 9.41 / 4.81（每百段） | 合并、拆分或调语序，打散其中一句 | — |
| Z4 | 破折号：制造"揭晓"停顿、插可有可无的补充 | 2.38 / 0.80 | 删；承担解释、插入、转折的保留；**作者本人爱用时按作者习惯** | 答案很简单——坚持。→ 答案是坚持。 |
| Z5 | 提示性冒号："核心是：""关键在于：""一句话总结：" | 0.29 / 0.08 | 提示语不承担信息就删，直接说 | 核心是：先修支付失败。→ 先修支付失败。 |
| Z6 | 空转句引出列表：以冒号收尾、去掉也不损失信息的引导句 | 0.29 / 0.03 | 改成完整的一句或删 | 几种常见情况：→ 这几种情况最常见。 |
| Z7 | 序数词当小标题：连续三个以上"一、二、三 / 第一、第二" | 0.19 / 0.06 | 删编号，保留标题文字；正文里的"首先……其次"不算 | 二、实施过程 → 实施过程 |
| Z8 | 拟人化喻体："像一位智慧的导师""就像一盏灯塔" | 0.018 / 0.002 | 换成这东西实际做了什么；具体的人当喻体（像个老师傅）、带来新理解的比喻保留 | 它像一位贴心的管家。→ 它会提醒你哪天该交房租。 |
| Z9 | 概括盖掉已有的具体："显著提升""大幅增长"，而同段已有数字 | 人类数字密度是 AI 的 2.8 倍 | 把已有数字提到概括词的位置；没有数字只恢复动词，**不许编数字** | 效率显著提升，耗时从两小时降到四十分钟。→ 耗时从两小时降到四十分钟。 |
| Z10 | 起手式："说白了""说穿了""先说结论" | 0.025 / 0.008 | 删，直接给判断 | — |
| Z11 | 过长前置定语：中心词前修饰超过 15 字 | 0.42（人类低 2.6–5.3 倍） | 拆成两个分句 | 一个能让团队不加人就提速的工具 → 这个工具能提速，不用加人 |
| Z12 | "当……时"前置从句 | 0.26 | 删"当"和"时" | 当用户第一次打开时，…… → 用户第一次打开，…… |
| Z13 | 前置话题壳："对于……来说""就……而言" | 0.22 | 把对象放主语位 | 对于新团队来说，招人最难。→ 新团队最难的是招人。 |
| Z14 | 句首连接词当路标："然而""因此""此外""综上所述"顶在句首 | 0.18 / 0.03 | 移到主语后，或换"不过、也"，或删 | 然而，预算有限。→ 预算却有限。 |
| Z15 | "这意味着 / 这表明"复述上一句 | 0.15 | 并入前句 | 留存涨到 72%。这意味着产品站住了。→ 留存涨到 72%，产品站住了。 |
| Z16 | 段首零主语评论：非首段以"值得注意的是""更重要的是""关键在于"开头且没有回指 | 0.61% / 0.14%（占非首段） | 清理模式补一个"这"；作者稿模式多半整句删 | 值得注意的是，…… → 这一点值得注意，…… |

## 5. 编辑刀（作者稿和新写模式；清理模式只用加粗的几条）

- **开头**：删"接下来让我们深入看看""以下是你需要知道的"；删"随着……的发展"这种没有信息的背景句；**删"本文分三部分"式的预告**。
- **段间**：**删"可见、由此、换句话说、更重要的是、翻译成人话"这类过渡和元话语**；标题下第一句只是复述标题的删；为制造节奏把一个意思拆成三段的合并。
- **结尾**：**删总结、升华、回收前文和金句收尾**，停在一个具体的地方；删"让我们拭目以待""未来可期"；有实际内容的行动计划保留。
- **句内**：副词"非常、十分、极大地、显著"默认可疑；**"也许可能大概"这类叠加的限定压成一层，但保留原有的不确定程度**；删句尾拔高（"彰显了……的不懈追求""标志着新时代"）；删"这说明、这是最动人的一句"之类替读者下的判断；生造的复合词换回它的意思；一段里成语超过两个多半在用气势代替内容。

## 6. 黑名单（命中不等于该删）

看上下文是不是空泛、重复、不准，再决定：

- 口头禅：众所周知、总而言之、综上所述、值得注意的是、不可否认、在当今时代
- 拔高词：赋能、至关重要、深入探讨、无缝、闭环、底层逻辑、抓手、对齐、打透、跑通、颠覆、重塑、生态、助力、赛道
- 官话：砥砺、打造、扎实推进、统一部署
- 滥情：令人深思、不禁让人、令人动容、一言难尽

有确切含义的术语照用：闭环控制、端到端加密、生态系统（生物学）。

## 7. 不许动（实测不是 AI 痕迹，乱改反而更不像人写的）

| 看着像 AI | 实测 | 所以 |
|-----------|------|------|
| 句长、段长不够参差 | 人机无差别 | 不为"制造节奏"调句长、拆段 |
| 句内排比（更快、更稳、更省） | 人类用得更多 | 保留；只改相邻句复用同一骨架（Z3） |
| 被动句、名词化、长句 | 现代书面语正常写法 | 不改；只有被动句把责任人藏起来、而文章要追责时才改 |
| 正文里的"首先……其次" | 无差别 | 保留；只管小标题编号（Z7） |
| 问句、设问、问句小标题 | 人类用得远多于 AI | 不删 |
| 比喻本身、比喻独立成段 | 人类用得更多 | 保留；只改拟人化喻体（Z8） |
| 反复写全称、少用代词 | 人类更常重复名词 | 不改 |
| 承担分量的虚词（已、竟然、反倒、所以） | — | 保留，删了反而失去语气 |
| 四字格 | 汉语本来的节奏 | 只改同义堆叠（稳定可靠、快速响应） |
| 邮件、客服回复里的问候和落款 | 有实际用途 | 只在独立文章里删 |

## 8. 分文体要点

| 文体 | 重点 |
|------|------|
| 公众号、自媒体 | 开头铺垫、金句收尾、粗体、惊叹号、emoji、翻案腔；保留作者口语和个人经历 |
| 工作汇报、方案 | 序数小标题、"显著提升"盖掉数字（Z9）、"赋能、抓手、闭环"、句首"此外 / 因此"；数据和结论一个不能少 |
| 产品介绍、营销文案 | 拟人化喻体、"不仅……更……"、拔高词、空转冒号；功能和参数原样保留 |
| 随笔、叙事 | 自造金句、作者不在场的编造细节（标 `[请作者补]`）、结尾升华 |
| 学术、技术文档 | 只做门槛和聊天残留，术语、长句、被动句保持 |
| 邮件、通知 | 删套话，保留问候、落款和礼貌用语 |

## 9. 流程和交付前核对

1. `ai_tone_check.py scan 原稿`，看偏高项和门槛；作者稿先用 `profile` 识别作者习惯；
2. 按模式改；
3. `ai_tone_check.py diff 原稿 改稿`："必须处理"的项全部解决，"请确认"的逐处看；
4. 再 `scan 改稿` 一次；
5. 人工核对：每处改动都能对应到一条规则；没有新增事实；否定、限定、范围、时间、归因没变；结构没动；通顺的地方没被硬改。

不以"字数变少""命中清零""AI 检测率"作为交付标准，事实和原意优先。
